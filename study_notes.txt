1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Workplace Knowledge Vault is an internal company web application where employees 
create, share, search, and manage internal technical documentation, guides, and policies.

Core Business Problem Solved:
In companies, knowledge is often scattered across chat messages or local files. 
Knowledge Vault provides a central repository with content moderation (Admin Approval), 
tag-based classification, and interactive social features (likes, comments, bookmarks).

3. DATABASE ARCHITECTURE (MICROSOFT SQL SERVER)
--------------------------------------------------------------------------------
The database 'KnowledgeVaultDb' consists of 8 relational tables:

1. Users: Stores account details (Id, Username, Email, PasswordHash, Role, CreatedAt)
2. Categories: Lookup table for knowledge topics (Id, Name, Description)
3. Articles: Stores articles (Id, Title, Content, Status, AuthorId, CategoryId, CreatedAt)
   - AuthorId -> Foreign Key to Users(Id)
   - CategoryId -> Foreign Key to Categories(Id)
   - Status -> 'Pending', 'Approved', or 'Rejected'
4. Comments: Discussion thread under articles (Id, ArticleId, UserId, Content, CreatedAt)
5. Likes: Tracks article likes (Id, ArticleId, UserId, CreatedAt)
6. Bookmarks: User's saved articles (Id, ArticleId, UserId, CreatedAt)
7. Tags: Named tags for search filtering (Id, Name)
8. ArticleTags: Junction Table (Many-to-Many) linking Articles and Tags with a composite key (ArticleId, TagId)

5. END-TO-END WORKFLOWS
--------------------------------------------------------------------------------
A. Authentication Flow:
1. User enters email and password on React login form.
2. React sends POST request to /api/auth/login.
3. .NET verifies password against BCrypt hash in Microsoft SQL Server.
4. .NET generates cryptographically signed JWT Bearer token containing User ID, Email, and Role.
5. React stores JWT token in localStorage.
6. Axios interceptor automatically attaches 'Authorization: Bearer <token>' to all outgoing HTTP requests.
7. .NET JwtBearer middleware validates token signature and role claims on every protected API call.

B. Article Moderation Workflow:
1. Employee writes an article -> Backend API saves it with Status = 'Pending'.
2. Pending articles are hidden from the main team feed.
3. Admin logs in and opens the Admin Panel (/admin).
4. Admin views pending articles and clicks 'Approve'.
5. Backend updates database status to 'Approved'.
6. Article immediately appears live on the public feed for all employees!

     const token = localStorage.getItem('kv_token')

7. VIVA & PRESENTATION QUESTIONS AND ANSWERS
--------------------------------------------------------------------------------
Q1: What architecture did you follow in this project?
A: "We followed a decoupled 3-tier REST architecture: React Single Page Application on the 
   frontend, ASP.NET Core 8 Web API for backend logic, and Microsoft SQL Server for database storage."

Q2: How do you store user passwords securely?
A: "Passwords are never stored in plain text. We hash them using the BCrypt algorithm (BCrypt.Net) 
   before saving them to the Users table in Microsoft SQL Server."

Q3: How does authentication work between React and .NET?
A: "Stateless JWT (JSON Web Tokens). Upon login, the server returns a signed token containing user claims. 
   React stores this in localStorage and sends it in the Authorization header on every HTTP request."

Q4: How did you handle relational database constraints?
A: "We defined Primary Keys, Foreign Keys with CASCADE/SET NULL behaviors, and Composite Unique Constraints 
   on Likes and Bookmarks to prevent duplicate entries per user."
